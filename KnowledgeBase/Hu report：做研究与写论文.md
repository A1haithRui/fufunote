# 做研究是一种思维模式
不能缺什么再找什么，这不应该是做研究的思维模式。
一个任务：首先主动搜索和获取信息，缺什么自己去找什么。以要调研的对象为核心目标。提供自己的视角。
研究的最终目的是未知边界的突破。

# 问题驱动的研究方法：碰到问题，确认问题，解决问题
确认了错误的问题，在错误的方向狂奔，不停地做各种实验，会极大地浪费精力。

# 做研究不是看书看论文，是动手
有人说这个实验效果非常好，我们需要提出：“不一定”。静态场景好的，动态场景会好吗？静态场景真的好吗？
如果是大厂的论文，一般的开源代码效果不会差。我们需要用他们的代码来验证。然后用批判性的思维来做一些批判性的实验。找出他们模型的退化之处。没有人敢说自己的工作是解决了所有问题。

# 带着问题做实验
通过实验和讨论确认问题后，来做实验解决问题。

# 区分哪些可以当而且必须当黑盒模块用
有些东西可以原封不动直接搬过来用。自己论文的主张，是不能当黑盒使用。这样自己的工作贡献极大降低且无法来展示自己的论文思想。
和个人主张没有极大关系的可以作为黑盒使用。
# 一次实验只改一个部分
如果改了很多个点，也只能描述一个点。

# 快速试错，修正，迭代
获得来自同学、老师的反馈后，需要反思目前的工作是否在正确的路上，路线是否正确。
# 获得有效反馈和帮助：区分什么是快什么是慢
需要详细展示我们的结果。不要展示做了的工作，而是展示具体的效果。不能说：“效果还行”，要说：“效果哪里还行，哪里不行，哪里是常理之中，哪里是意想不到”。需要在汇报中做出分析，这样才能得到建议。否则自己不知道问题在哪，老师朋友也不知道问题在哪。

# 论文的本质是交流，是提供信息量
论文不是什么高大上的东西，是一种交流。跟你在知乎论坛上发帖没本质区别。展示自己的想法和发现。
确定什么是已知的，什么是未知的。如果一直在写已知的东西，那就是不入流的论文。

# 从读者视角写论文
虽然一般审稿的都是同行。但是我们写的时候不能假设读者知道我们所知道的。这也是我们需要不断迭代论文的原因。
如果审稿看不懂，他也不想看懂，也不想承认自己看不懂，那你不是就寄了吗。
用gpt、deepseek工具来润色语言是必要的，因为语法问题不能出现。
# 写论文的重点不是语言，是逻辑
因为所以，不合逻辑。
论文最重要的还是逻辑。
“因为这个sota不好，所以我提出了这三个点”
这句话就不合逻辑。“因为不好”并不是原因，而是现象。需要分析的是：“不好”的原因。“因为这个sota的xxx导致了它不好，所以我提出了这三个点”
# 一个论文只讲一件事
哪怕你一个模块提供了15个点，但是一次性写五个模块，论文档次就降低了。
我们需要只讲一件事情，把这件事情讲清楚。分析原因和逻辑，而非堆砌模块。这样论文才是上流的。
# 坦诚，合理，充分的基线与实验设计
很多基线实验明显不合理。你选一个十年前的基线，提了五十个点。这个投出去就只能看运气了。审稿人不知道还好，知道的话这种行为就是浪费自己的时间和精力。投出去之后审稿人还要让你继续改基线和实验。这样还不如你直接投一篇高质量。
# 高质量论文写作的一些基本点：
总的来说就是精简，平铺直叙。
- 少用短句
- 少用被动结构
- 少用代词
- 少用缩写（如果是自己提出的东西尽量不要缩写）
- 标点符号用对（比如括号前面要加空格）
- 大小写用对
# 高质量论文各个部分的一些基本点：
- 标题：需要最大程度反应信息量
- 介绍： 能展示论文基本80%的内容（老师也会着重改这里）
- 相关工作：重点要强调我们的不同（However）
- 方法：不要大段去写已经存在的东西，一句话概括就行。关注点在于我们不同的地方
- 实验
- 结论：短，但是尽量被搬介绍，用完成时态即可
- 参考文献：问题挺多的，要把名称搞一致。需要着重检查
