## 2. 先纠正核心认识

九齿的 `application` 不只是数学表达式。当前 `ninetoothed 0.25.0` 的官方测试已经验证以下能力：

```python
input.source[dynamic_indices]
output.source[dynamic_indices] = value
input.source.data_ptr()
input.offsets(dim)
input.source.stride(dim)
ntl.load(pointer)
ntl.store(pointer, value)
ntl.atomic_add(pointer, value)
```

因此九齿可以编写 output-driven gather/scatter kernel：

1. arrangement 将输出域切成 block；
2. application 根据每个输出位置计算输入位置；
3. 从 `input.source` 动态读取；
4. 写入当前输出位置或 `output.source` 的指定位置。

官方依据：

- `ninetoothed/tests/test_clone.py`：动态 source 索引、手工指针寻址、动态 store；
- `ninetoothed/tests/test_data_ptr.py`：`ntl.atomic_add`；
- `ninetoothed/tests/test_pad.py`：Python 分析 shape/slice，arrangement 负责切片，application 只做搬运；
- `ninetoothed/src/ninetoothed/tensor.py`：`tile/expand/flatten/permute/pad/__getitem__` 的索引映射实现。

### 合理的 Python 工作

Python wrapper 可以负责：

- 参数合法性检查和归一化；
- 负维度处理；
- shape 推导；
- 输出张量分配；
- 将参数整理为 kernel metadata；
- 对变长输入/多输出进行多次 kernel launch；
- kernel 缓存。

Python wrapper 不应负责：

- 调用 `torch.roll/torch.mode/torch.meshgrid/...` 得到最终结果；
- 在 PyTorch 中完成主要数值计算，再让九齿复制；
- 在提交实现里把参考算子作为 fallback 偷渡进去。

identity application 并不等于没有实现。数据搬运算子的核心可以完全位于 arrangement 的索引映射中；官方 `test_pad.py` 就采用了这种结构。

## 4. 公共实现范式

### 4.1 一维输出域

对于形状保持或输出可 flatten 的算子，优先将输出整体展平后 tile：

```python
def arrangement(input, output, block_size=None):
    if block_size is None:
        block_size = ninetoothed.block_size()

    input_arranged = input.flatten().tile((block_size,))
    output_arranged = output.flatten().tile((block_size,))

    return input_arranged, output_arranged
```

不要对 N 个维度分别使用 `(BLOCK_SIZE, BLOCK_SIZE, ...)`，否则 tile 体积会指数增长。`flatten().tile((BLOCK_SIZE,))` 可以让一个 block 处理一段线性输出；尾部越界 lane 由 mask 处理。

### 4.2 动态 gather

官方推荐线索来自 `test_clone.py`：

```python
value = input.source[index_0, index_1]
```

或手工构造地址：

```python
pointer = input.source.data_ptr()
pointer += index_0 * input.source.stride(0)
pointer += index_1 * input.source.stride(1)
value = ntl.load(pointer)
```

手工地址形式更适合需要遍历任意 `ndim` 的算子。

### 4.3 动态 store

```python
output.source[index_0, index_1] = value
```

适合 `column_stack`：输入按照自己的连续 block 读取，application 将它写到输出的列偏移位置。

### 4.4 多 kernel launch

对于变长输入列表和多输出算子，多次 launch 是合理工程方案：

- `column_stack`：每个输入一次 launch；
- `meshgrid`：每个输出一次 launch；
- `cartesian_prod`：每个输出列一次 launch。

这比在 Python 调参考算子更符合赛题要求。提交前应向赛题组确认是否允许组合多个 NineToothed kernel 实现一个高层算子。

## 5. `meshgrid`：第一优先级

### 5.1 数学映射

对于输入 `x_i`，对应输出网格 `out_i` 的每个位置只取决于第 `target_dim` 个坐标：

```text
out_i[index_0, ..., index_n] = x_i[index_target_dim]
```

`indexing="ij"` 时，输入 i 对应维度 i。

`indexing="xy"` 时，前两个输入的目标维度互换：

```text
input 0 -> dim 1
input 1 -> dim 0
input i -> dim i, i >= 2
```

### 5.2 推荐实现

每个输入/输出对单独调用一次 kernel。在 arrangement 中：

1. 给一维输入插入 singleton 维；
2. `expand(output_shape)` 得到概念广播视图；
3. 将广播视图与输出都 flatten；
4. 使用一维 tile；
5. application 写 `output = input`。

概念代码：

```python
def arrangement(input, output, target_dim, output_shape, block_size=None):
    arranged = input

    for _ in range(target_dim):
        arranged = arranged.unsqueeze(0)

    for _ in range(len(output_shape) - target_dim - 1):
        arranged = arranged.unsqueeze(arranged.ndim)

    arranged = arranged.expand(output_shape)

    return (
        arranged.flatten().tile((block_size,)),
        output.flatten().tile((block_size,)),
    )


def application(input, output):
    output = input
```

这段需要根据实际 `Symbol`、`block_size` 和 `_cached_make` 接口调整，但索引方案应保持不变。

### 5.3 必测用例

- 单输入；
- 两个输入，`indexing="ij"`；
- 两个输入，`indexing="xy"`；
- 三个输入；
- 不同长度，如 `(2, 3, 5)`；
- `float16/float32/int32`；
- 标量输入是否按长度 1 处理；
- 输出 shape、dtype、device、数值全部一致。

## 6. `cartesian_prod`：第二优先级

### 6.1 数学映射

假设输入长度为：

```text
L0, L1, ..., Ln-1
```

输出行为 `row`、输出列为 `col`。第 `col` 个输入的读取位置为：

```text
repeat_after[col] = product(L[col + 1:])
source_index = (row // repeat_after[col]) % L[col]
```

因此不需要真正构造 meshgrid 中间结果。

### 6.2 推荐实现

每个输入负责输出的一列，每列调用一次 kernel：

```python
def application(input, output, repeat_after):
    row = output.offsets(0)
    source_index = (row // repeat_after) % input.source.shape[0]
    output = input.source[source_index]
```

arrangement 需要让 `output` 表示 `output[:, column]`，并沿行方向 tile。`column` 和 `repeat_after` 可以由 wrapper 根据输入长度计算，它们属于 metadata，不是参考计算。

### 6.3 必测用例

- 1 个输入；
- 2 个不同长度输入；
- 3 个输入；
- 长度包含 1；
- 整数和浮点 dtype；
- 输出行顺序必须与 PyTorch 完全一致。

## 7. `roll`：第三优先级

### 7.1 指定 dims 的映射

先在 wrapper 中把 `(shifts, dims)` 归一化为长度 `ndim` 的 `shift_per_dim`：

```text
source_index[d] = (output_index[d] - shift_per_dim[d]) % size[d]
```

重复维度需要累加 shift，并最终对该维长度取模。

### 7.2 推荐 application 形态

```python
def application(input, shifts, output):
    pointer = input.source.data_ptr()

    for dim in range(input.source.ndim):
        source_index = (
            output.offsets(dim) - shifts.source[dim]
        ) % input.source.shape[dim]

        pointer += source_index * input.source.stride(dim)

    output = ntl.load(pointer)
```

`shifts` 可以先用一个很小的 GPU int tensor 实现正确性。性能优化阶段再考虑 constexpr/specialized kernel，避免现在卡在动态 application 签名上。

### 7.3 `dims=None`

`dims=None` 不是“每个维度都 roll”，而是：

1. 逻辑上 flatten 输入；
2. 对 flat index 做 roll；
3. 将 source flat index unravel 为原张量坐标；
4. 使用原张量 stride 构造读取地址。

建议单独写一个 flat kernel，不要与指定 dims 的版本硬塞进同一条路径。

### 7.4 必测用例

- `dims=None`；
- 单维正 shift、负 shift、0；
- `abs(shift) > size`；
- 多维 `(shifts, dims)`；
- 负维度；
- 重复维度；
- 非 contiguous 输入；
- shape 保持不变。

若非 contiguous 输入暂时失败，可以先记录为已知问题，但不要悄悄调用 `contiguous()` 而不评估额外复制成本。

## 8. `column_stack`：第四优先级

### 8.1 语义拆分

- 一维输入 `(N,)` 视作 `(N, 1)`；
- 二维及以上输入沿 `dim=1` 拼接；
- 除拼接维外，其余维度必须匹配。

### 8.2 推荐实现

wrapper 只计算每个输入在输出中的列前缀：

```text
column_offset[i] = sum(width(input_j), j < i)
```

每个输入调用一次 kernel。application 读取当前输入 block，然后写入：

```text
output column = input column + column_offset
```

可以采用两种方式：

1. arrangement 对 output 做静态 slice，application 为 identity；
2. application 使用 `output.source[...] = input` 动态 store。

优先选择第二种，避免不同列宽生成大量 slice 特化 kernel。第一种仍然是合法九齿方案，官方 `test_pad.py` 已使用类似结构。

### 8.3 必测用例

- 两个一维输入；
- 一个一维输入；
- 多个二维输入，列宽不同；
- 输入数量大于 2；
- 除 dim=1 外 shape 不匹配时的报错；
- dtype/device 不一致时与 PyTorch 行为对齐；
- 空输入或零长度维度。

## 9. `mode`：最后处理

`mode` 不是纯数据重排布，而是“按指定维规约并返回 value/index”。不要继续使用：

```python
torch.mode(input)
```

作为提交实现。

### 9.1 第一版正确性算法

每个 reduction row 由一个 program 处理。对于规约维中的每个候选值：

```text
candidate = input[j]
count = sum(input == candidate)

如果 count 更大：更新 best_value/best_count/best_index
如果 count 相同：按 PyTorch 的 tie-breaking 更新
```

这是 O(K^2) 算法，但可以先得到真正的九齿正确实现。输入 tile 已加载后，比较和计数发生在 application 内，不需要 Python 参与。

### 9.2 必须先探测 PyTorch 语义

在写 kernel 前用小脚本确认：

- 两个值出现次数相同时选择哪个 value；
- 相同 mode value 出现多次时返回哪个 index；
- `keepdim=True/False`；
- 默认 `dim=-1`；
- `NaN`、整数和浮点的行为；
- CUDA 上当前 PyTorch 版本是否支持参考执行。

将这些行为写成固定 pytest，不要只使用随机测试。

### 9.3 止损条件

如果 `mode` 在 2.5 小时内仍未形成可运行 kernel，停止继续投入，转去完善前 4 个算子的测试、文档和提交材料。

## 12. 最小性能检查

正确性完成后，用 CUDA Event 测试 wrapper 总耗时，不要只测 kernel：

```python
starter = torch.cuda.Event(enable_timing=True)
ender = torch.cuda.Event(enable_timing=True)

for _ in range(20):
    op(...)

torch.cuda.synchronize()
starter.record()
for _ in range(100):
    op(...)
ender.record()
torch.cuda.synchronize()

milliseconds = starter.elapsed_time(ender) / 100
```

重点观察：

- 多 launch 开销；
- wrapper 是否每次新建 GPU metadata tensor；
- 输出写入是否连续、合并；
- block size 固定为 128/256/512 时的差异；
- 自动调优关闭后是否仍有合理默认配置。

剩余 15 小时内只做显而易见的优化，不做架构重写。
