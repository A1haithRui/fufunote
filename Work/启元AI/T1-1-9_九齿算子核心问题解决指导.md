# T1-1-9 九齿算子核心问题解决指导

## 1. 当前结论

T1-1-9 包含：

- `frac`
- `scatter_add`
- `multilabel_margin_loss`
- `fractional_max_pool2d`
- `fractional_max_pool3d`

这五个算子并未超出九齿的绝对能力边界。当前真正可用的关键能力是：

```python
tensor.offsets(dim)
tensor.source.data_ptr()
tensor.source.stride(dim)
tensor.source.shape[dim]
ntl.load(pointer)
ntl.atomic_add(pointer, value, mask=mask)
```

因此：

- `scatter_add` 使用手工目标地址和 `ntl.atomic_add`；
- fractional max pool 使用 output-driven gather；
- `multilabel_margin_loss` 使用一行一个 program 的向量化规约；
- Python wrapper 只做 shape、参数和 launch metadata 处理。

不应继续采用以下方案：

```text
torch.scatter_add_ 计算结果
torch.multilabel_margin_loss 计算结果
torch.fractional_max_pool* 计算结果
九齿 kernel 只负责复制最终结果
```

## 2. 推荐推进顺序

1. 固化并复核 `frac`；
2. 完成 `scatter_add`；
3. 完成 `fractional_max_pool2d`；
4. 复用 2D 设计完成 `fractional_max_pool3d`；
5. 最后重写 `multilabel_margin_loss`。

不要让 `multilabel_margin_loss` 的编译问题阻塞其他三个可直接落地的算子。

## 3. `frac`

### 3.1 数学定义

```text
frac(x) = x - trunc(x)
```

负数的结果保留负方向，例如：

```text
frac(-2.75) = -0.75
```

### 3.2 九齿实现

它是标准 element-wise 算子，可直接复用：

```python
from ntops.kernels.element_wise import arrangement
```

application 的核心应为：

```python
def application(input, output):
    output = input - ntl.trunc(input)
```

若当前 Triton/九齿版本没有 `ntl.trunc`，优先探测对应 libdevice 实现。不要简单转成 `int64` 后再减，因为 `inf/nan`、超大浮点数和整数范围会产生错误或未定义行为。

### 3.3 必测项

- 正数、负数和 0；
- `float16/float32/float64`；
- 大浮点数；
- `inf/-inf/nan`；
- 非连续输入；
- `out=` 参数；
- exact shape、dtype 和 device。

纯数据运算可使用 `torch.equal(..., equal_nan=True)` 或针对 NaN 单独比较。

## 4. `scatter_add`

## 4.1 正确分层

`torch.scatter_add(input, dim, index, src)` 的结果包含两部分：

```text
output = input
output[target_position] += src[source_position]
```

因此建议拆成两个九齿 kernel：

1. identity kernel：将 `input` 复制到 `output`；
2. atomic kernel：将 `src` 按 `index` 原子累加到 `output`。

不能直接用 `torch.clone` 或 `torch.scatter_add_` 替代这两步，否则核心数据操作仍由 PyTorch 完成。

### 4.2 atomic kernel 的地址计算

每个 lane 对应一个 `src` 元素。其输出坐标为：

```text
coord[d] = src_position[d], d != dim
coord[dim] = index[src_position]
```

然后构造目标指针：

```text
output_ptr = output_base
           + coord[0] * output_stride[0]
           + coord[1] * output_stride[1]
           + ...
```

概念代码：

```python
def application(index, src, output):
    pointer = output.source.data_ptr()

    # 以下维度访问应按 (ndim, dim) 特化展开
    pointer += src.offsets(0) * output.source.stride(0)
    pointer += index * output.source.stride(1)  # 假设 dim == 1
    pointer += src.offsets(2) * output.source.stride(2)

    ntl.atomic_add(pointer, src, mask=valid_mask)
```

不要使用 `ntl.call("atomic_add", ...)`；application 中直接写 `ntl.atomic_add(...)`。

### 4.3 为什么要特化

九齿代码生成器要求 `source.stride(dim)` 中的 dim 能在生成期确定。因此可建立：

```python
_APPLICATIONS[(ndim, normalized_dim)]
```

第一版至少支持比赛隐藏测试最可能覆盖的 1D-4D；时间允许再扩到 8D。

### 4.4 mask

flatten+tile 的最后一个 block 会存在越界 lane。atomic 操作不会自动继承普通 output store 的 mask，因此必须显式构造：

```text
valid = 对所有 src 维度检查 0 <= offsets[d] < src.shape[d]
```

并传给：

```python
ntl.atomic_add(pointer, src, mask=valid)
```

index 越界时 PyTorch 会报错。竞赛实现可以先假设测试输入合法，但必须保证合法输入下尾部 padding lane 不会写坏 output。

### 4.5 wrapper 校验

- 标准化负 dim；
- 检查 `index.dtype == torch.int64`；
- 检查 index 与 src 的维度关系；
- 检查除 dim 外的尺寸不超过 output；
- 空 index/src 直接返回 input 的九齿复制结果；
- 不要让 `zip` 等逻辑静默截断参数。

### 4.6 必测项

- 无重复 index；
- 大量重复 index；
- dim=0/1/-1；
- src/index 尺寸小于 input；
- 空 index；
- 非连续 input/src；
- `float16/float32/int32`；
- 多次运行，确认不存在非原子竞争导致的随机错误。

原子支持与精度依赖后端，必须分别记录 NVIDIA 和国产平台的实际支持情况。

## 5. `multilabel_margin_loss`

### 5.1 当前版本必须推翻的部分

当前三层循环为：

```text
positive j
    negative candidate i
        扫描 target k 判断 i 是否为 positive
```

其复杂度是 O(C^3)，会导致生成代码巨大、编译慢和运行性能差。

当前 `num_pos` 逻辑还无法正确表示第一个 target 就是 `-1` 的情况；无效 target 位置也可能触发 `input[..., -1]` 或越界读取。

不要继续修补该版本，应改为 O(C^2) 向量化实现。

### 5.2 arrangement

目标是：

```text
每个 program 处理一个 batch row
一个 row 内同时持有 input[batch, :]
一个 row 内同时持有 target[batch, :]
规约维 padding 到 BLOCK_C
```

建议：

1. wrapper 读取具体 C；
2. 计算 `BLOCK_C = next_power_of_2(C)`；
3. premake 使用 concrete C/BLOCK_C，先保证正确性；
4. arrangement 只 tile 一次，不再使用当前的二次 `tile((-1, C))`；
5. 参考已有 `reduction.arrangement` 的“非规约维为 program、规约维为 inner tile”结构。

当前 autotune 的 Symbol 报错更可能是错误的二次 tile 将动态尺寸放入 innermost shape，而不是必须修改九齿 Symbol 系统。

### 5.3 构造 positive mask

先创建类别位置：

```text
class_ids = [0, 1, ..., BLOCK_C-1]
valid_class = class_ids < C
```

遍历 target 的有效前缀，构造：

```text
positive_mask[class] = 该 class 是否出现在有效 target 中
```

概念逻辑：

```python
positive_mask = false_vector
seen_negative = False

for j in range(BLOCK_C):
    valid_position = (j < C) & (~seen_negative) & (target[j] >= 0)
    safe_class = ntl.where(valid_position, target[j], 0)

    positive_mask |= valid_position & (class_ids == safe_class)
    seen_negative |= (j < C) & (target[j] < 0)
```

这样能正确处理第一个元素就是 `-1` 的零 positive 情况。

### 5.4 计算 loss

对每个有效 positive 只保留一层循环：

```python
loss = 0

for j in range(BLOCK_C):
    valid_pos = ...
    pos_class = ...

    # 避免动态 gather：用向量匹配取出 input[pos_class]
    pos_value = ntl.sum(
        ntl.where(valid_class & (class_ids == pos_class), input, 0)
    )

    margins = ntl.maximum(0, 1 - pos_value + input)
    negative_mask = valid_class & (~positive_mask)

    loss += ntl.where(
        valid_pos,
        ntl.sum(ntl.where(negative_mask, margins, 0)),
        0,
    )
```

最终：

```text
per_sample_loss = loss / C
```

该方案仍是 O(C^2)，但避免第三层循环，也不依赖 application 动态下标。

### 5.5 reduction 参数

先生成 per-sample loss：

- `reduction="none"`：直接返回；
- `reduction="sum"`：第二个九齿 kernel atomic add 到标量；
- `reduction="mean"`：每个样本先除以 N，再 atomic add。

标量输出必须先用九齿或合法初始化方式清零。不要调用 `torch.sum/mean` 完成最终规约。

### 5.6 必测项

- 1D input/target；
- batched 2D；
- 零 positive；
- 一个 positive；
- 多个 positive；
- target 中重复 class；
- `none/sum/mean`；
- float16/float32；
- C 为非 2 的幂；
- 与固定手算样例对比，不只使用随机测试。

## 6. `fractional_max_pool2d`

### 6.1 首先修正算法认识

`_random_samples` 的形状为：

```text
(N, C, 2)
```

最后一维分别提供 H/W 方向的随机样本。它不是每个输出位置一个随机数，因此不能对 `_random_samples` 做 cumulative sum 来生成窗口序列。

对单个空间维，必须用固定 `_random_samples` 与当前 PyTorch 版本验证区间公式。常见实现为：

```text
alpha = (input_size - kernel_size) / (output_size - 1)

start[i] = floor((i + sample) * alpha) - floor(sample * alpha)
start[last] = input_size - kernel_size
```

`output_size == 1` 时应直接使用最后窗口位置，避免除 0。

不要凭文字描述实现。先为一个很小的输入固定 `_random_samples`，用 PyTorch 输出 value/index 反推出每个窗口起点，并将其写成固定测试。

### 6.2 output-driven kernel

arrangement 只需将 output domain flatten 后 tile。application 对每个输出位置：

1. 从 output offsets 得到 `n/c/oh/ow`；
2. 加载 `_random_samples[n, c, 0/1]`；
3. 计算 `start_h/start_w`；
4. 使用固定 `kH/kW` 循环访问输入窗口；
5. 跟踪最大值及其扁平化输入 index；
6. 写入 values 和 indices。

概念地址：

```text
input_ptr = input_base
          + n * stride_n
          + c * stride_c
          + (start_h + kh) * stride_h
          + (start_w + kw) * stride_w
```

窗口起点虽然动态，但 `kH/kW` 是 wrapper 参数，可作为 constexpr 让循环在生成期展开。

### 6.3 index 语义

返回 index 通常是输入空间维的扁平索引：

```text
index_2d = input_h * W + input_w
```

必须用 PyTorch 固定样例验证 tie 时选择第一个还是最后一个最大值。

### 6.4 wrapper

- 支持 batched `(N,C,H,W)`；
- 支持 unbatched `(C,H,W)`，内部可视作 N=1；
- 标准化 `kernel_size`；
- `output_size` 与 `output_ratio` 二选一；
- 根据 `output_ratio` 推导 output shape；
- `_random_samples=None` 时生成符合 PyTorch 形状与 dtype 的随机样本；
- `return_indices=False` 时仍可内部计算 index，但只返回 value。

生成 `_random_samples` 属于参数准备，但应在 `REFERENCE.md` 中如实说明。

## 7. `fractional_max_pool3d`

3D 与 2D 共用同一设计：

```text
random_samples shape: (N, C, 3)
output offsets: n/c/od/oh/ow
动态起点: start_d/start_h/start_w
固定循环: kD/kH/kW
```

输入地址：

```text
input_ptr = input_base
          + n * stride_n
          + c * stride_c
          + (start_d + kd) * stride_d
          + (start_h + kh) * stride_h
          + (start_w + kw) * stride_w
```

返回扁平 index：

```text
index_3d = (input_d * H + input_h) * W + input_w
```

建议先让 2D 的窗口公式、max tie 和 index 语义完全对齐，再复制扩展到 3D。不要并行调试两套公式。

## 8. fractional pool 必测项

- 固定 `_random_samples`，不要只测随机输入；
- batched/unbatched；
- `output_size` 为 int/tuple；
- `output_ratio`；
- `return_indices=True/False`；
- output 某维为 1；
- kernel size 为 1；
- 最大值重复时的 index；
- float16/float32；
- 非连续输入；
- 2D 和 3D 使用相同测试构造方法。
