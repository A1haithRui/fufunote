# 通过SSH反向代理实现内网服务器上网

## 情况

实验室服务器目前只能在连接内网的时候才能通过SSH访问，且没有接入互联网，不能在线配置环境。

如果没有连接内网（校园网），可以通过easy connect挂校园网的代理。但是没有接入互联网，配置环境、下载数据集很麻烦。

最开始我是通过在本地Windows系统配置好conda环境后用`conda pack`指令打包，然后上传服务器再解压，使用`source`指令即可完成环境的离线创建。但是有些环境只能在Linux系统配置。

后来我开始考虑用WSL2和租的云服务器来配置环境，虽然比较麻烦，但是可以实现离线环境配置。但是有时候下载数据也会很麻烦，几个G的数据传来传去很不方便。

## 解决方案

在网上看了这样一篇博客：[通过SSH反向代理实现内网服务器上网 - 知乎 (zhihu.com)](https://zhuanlan.zhihu.com/p/688754897)

可以通过SSH远程端口转发的方式，来让服务器接入互联网。

## 操作方式

### step1 查询端口

首先，需要知道自己的服务器IP地址：``xx.xx.xx.xx``，以及自己的用户名：``username`,一般情况下，使用SSH连接服务器需要通过以下指令：

```shell
ssh username@xx.xx.xx.xx
```

接下来，需要在自己本地下载软件Clash，并且打开System Proxy，这里可以在软件上看到，混合代理端口被默认设置为`7890`

*这里不是挂代理上外网，所以不需要导入节点*

### step2 开启端口转发

接着，`windows`+`R`输入`cmd`在本地开启一个终端，*后续这个终端不能关掉，因为它是用来进行端口转发的*，执行一下指令：

```shell
ssh -R 127.0.0.1:7891:127.0.0.1:7890 username@xx.xx.xx.xx
```

比如我的指令应该是：

```shell
ssh -R 127.0.0.1:7901:127.0.0.1:7897 difanrui@10.171.21.60
```

这里不需要修改`127.0.0.1:7891:127.0.0.1:7897`，它把服务器上的`7891`端口的流量转发到本地`7897`的端口上，而`7897`对应的就是Clash的混合代理端口。
*这个本地的port居然会改变，以前是7890，现在变成了7897，还好查到了*
### step3 将服务器上的流量转发

在服务器的终端上执行如下指令，将服务器上的`https`和`http`的流量转发到端口`7891`

```shell
export https_proxy=http://127.0.0.1:7891 http_proxy=http://127.0.0.1:7891 all_proxy=socks5://127.0.0.1:7891
```

这样就可以在服务器上联网配置环境了。但是目前看来是无法ping到一些网站的，有待继续考察。

### step other 将export添加到环境变量

打开终端并编辑 `.bashrc` 文件：

```bash
nano ~/.bashrc
```

或者使用其他编辑器，例如 `vim`、`gedit` 等。

在文件末尾添加以下内容：

```
export https_proxy=http://127.0.0.1:7891
export http_proxy=http://127.0.0.1:7891
export all_proxy=socks5://127.0.0.1:7891
```

保存并退出编辑器（在 `nano` 中按 `Ctrl + O` 保存，`Ctrl + X` 退出）。

使改动生效：

```
source ~/.bashrc
```
